## Delta Timer badge text always fits (1.18.1) — decisions
- Dutch's note: in the stacked Delta Timer, when the widget is resized the difference and its arrow did not fit the badge (text stuck out on the right); text size fixes it but changes everything. Wanted: the difference together with the arrow always fits the rectangle.
- Cause: the badge text is sized from the widget's text size (cqw), the badge width from the widget width (or a share of it), so a narrow widget, a long difference (+1:02.345) or a smaller "Size of the badge" left the text wider than the badge. Measured in a real browser over 324 sizes: 108 stacked cases overflowed before, 0 after.
- Decision: a fit step like the weather widgets (1.16.1) and leaderboard cells: `Delta.fit(root)` measures each `.dlt-badge` (text range + padding vs the badge's client box; the height need is 1.1 x the font size) and sets a smaller `font-size` in em of the widget (`!important`, rounded down to hundredths, never below 20%, at most three passes). The size from the markup (Size of the badge) is kept in `data-fit` and put back before every fit, so a widget that grows gets its full text back. A badge that fits is not touched. No markup change (tests and old layouts unaffected).
- Where it runs: `LiveCanvas.paint` (after each innerHTML of a widget with a badge) and a ResizeObserver per Delta widget in `LiveCanvas.build` (Race tab, full screen, Live Race pages); `drawCanvas` of the Layout Editor (also during a drag); `liveview.js` boards with row designs.
- Not changed on purpose: the value text and the layout. A stacked widget too short for value plus badge, or a side-by-side widget too narrow for both, still needs a bigger widget or smaller text size (the hint says so). The badge text itself is what shrinks.

## Delta Timers top and bottom (1.18.0) — decisions
- Dutch's question: could the Delta Timer also be shown vertically (top and bottom) instead of only left and right? Yes: new setting `direction` ("Value and badge") in all eight Delta Timers, `row` (standard, left and right) or `column` (the value on top, the badge below). Anything but `column` is `row`, so old widgets look as before. `Delta.layoutOf(opt)`.
- Markup: `Delta.wrap` adds the class `dlt-col` to `.dlt`; CSS in styles.css (`.dlt.dlt-col`: column flex, value `flex:1 1 0`, badge full width, line-height 1.1). The value is always first in the markup. The value on top; a badge-on-top variant was not asked for and is not built.
- Badge size in a column: `badgeScale` makes the badge a share of the WIDTH (`width:min(100%,calc((100% - .32em)*k))`, centred) instead of the height; the text scales the same in both. At 100% nothing is added to the style and the stylesheet makes the badge as wide as the widget.
- The widget keeps its default size (290 x 60), which is tight for a column: the hint says to make it taller or the text smaller. Not auto-resized on purpose (it could overlap other widgets).
- Label "Left value shows" became "Left (or top) value shows" (key `leftShows` unchanged); the help folder and tests follow.
- Option order in the editor: measure, compare, targetLane, leftShows, direction, decimals, style, ... (tests assert the key order).
